# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | The diff's changed files and hunks, read against the plan-context block's scope pair (in-scope and not-in-scope) and the plan's deviation notes. | Every file the diff touches falls inside the plan's stated scope or is covered by a deviation note. If the diff changes a file or adds a behavior the plan does not name and no deviation note explains the addition, it fails (silent addition). If the plan names a change the diff does not contain and no deviation note explains the omission, it fails (silent omission). An honest deviation note that explains why the diff differs from the plan re-ties the mismatch and passes. | required |
| description-matches-diff | The PR description's claims about what changed, read against the diff's actual contents. | The description accurately states what the diff does: files changed, behavior added or removed, scope of the fix. If the description claims a change the diff does not contain, or the diff contains a change the description does not mention, it fails. The description need not list every line — it must be truthful about what it claims. | required |
| test-evidence-decisive | The PR's test-evidence section (before/after output), read against the plan-context block's test plan and the reproduction's observed behavior. | The test evidence shows an observable behavior change: a before state matching the reproduction's output (the bug present) and an after state showing the fix (the bug absent). The expected-after must differ from the before in the way the plan's test plan predicted. If the evidence says only "tests pass" without showing what changed, it fails. An honest "cannot reproduce after fix" with the passing output shown passes. | required |
| repo-checks-run | The PR's test-evidence section or CI output, read for evidence that the repo's own test suite or linter was executed. | The PR shows evidence that the repo's own automated checks (test suite, linter, type checker) were run against the branch, with their outcome visible (pass or fail with explanation). If no evidence of running the repo's checks exists, it fails. A failing check with an honest explanation of why it fails (pre-existing failure, unrelated to this change) passes. | required |
| diff-reviewable | The diff's hunks and commit list, read for unrelated changes, debug leftovers, or formatting churn. | The diff contains only changes related to the fix described in the plan. No debug print statements, no commented-out code left behind, no formatting-only changes to untouched files, no drive-by refactors or unrelated cleanups. If the fix is buried under unrelated hunks that a reviewer must read through to find the actual change, it fails. | required |
| standards-followed | The PR description and title, read against the repo-facts block's PR template sections, contributing instructions, and stated AI-use disclosure policy. | The PR fills in the repo's stated template sections with real content (not placeholders). If the repo requires AI-use disclosure and the PR does not include one, it fails. If the repo's contributing guide names specific asks (e.g., link the issue, describe the change, show test evidence) and the PR ignores them, it fails. Silence in the repo's policy (no template, no disclosure requirement) counts as pass. | required |
| shortfall-disclosed | The PR description's limitations or known-issues section, read against the diff and the plan's risks. | If the fix has a known limitation, a deferred edge case, or a plan deviation, the PR description states it. A PR that honestly discloses a shortfall passes. A PR that silently omits a known limitation fails. If the fix is complete with no limitations, stating "no known limitations" or omitting the section passes. | preferred |

## Verdict rule

Accept if every required check passes. Reject if any required check fails. Unclear on any required check counts as fail. Preferred checks never change the verdict; they rank accepted PRs.
